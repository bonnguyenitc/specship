# Lessons — process mistakes and the rules that prevent them

- L1 — 2026-07-13 22:41 +0700 [TASK-005, review] mistake: AC3 was approved from a grep over a preselected five-skill list even though other skills also delegate, so R3/R4 coverage was missed → rule: derive the full affected set from a repository-wide delegation search and semantically inspect each fallback before approving a universal requirement.
- L2 — 2026-07-17 11:28 +07 [TASK-006, coding] mistake: S1 was ticked as covering AC2 because its verify (`node test/pipeline.test.js`) exited 0, but the fixture exercised only `resume_phase: 'coding'` — the `review` half that AC2 enumerates was never tested and turned out to be a deadlock, so a green gate certified a broken contract → rule: before ticking a step that names `covers: AC#`, enumerate the cases that AC# lists and point at the assertion covering each one; a passing verify command proves the fixtures you wrote, not the coverage you claimed.
- L5 — 2026-07-17 13:52 +07 [TASK-006, debug] mistake: the fix for BUG2 (parser dropped an `artifacts:` map after a comment) introduced an infinite loop on an unterminated fence — an input the same function already had an error message for — and it survived my own re-read plus a 69-test green gate; an independent reviewer of the fix caught it → rule: after changing a parser or validator, replay the malformed inputs it already claims to handle as tests before calling the fix done, and get eyes other than your own on a fix — the author of a fix is the worst judge of what it broke.
- L4 — 2026-07-17 11:58 +07 [TASK-006, review] mistake: a review follow-up proposed deleting `resume_phase` because "the gate never reads it" — true, but the field's real consumer is the debug *agent*, and acting on it would have broken the debug loop the same review had just fixed → rule: before calling a field, flag or code path dead, enumerate its consumers across every reader — including agents reading it as instructions, not just the code you happen to be looking at — and name them; "the component I read doesn't use it" is evidence about that component, not about the field.
- L3 — 2026-07-17 11:28 +07 [TASK-006, coding] mistake: the shipped skill text (`debug/SKILL.md`: "set `next_phase:` back to that phase") instructed an action the gate implemented in the same change rejects, and nothing caught it because prose and code were verified separately → rule: when one change ships both an instruction for agents and the code that enforces it, execute the instruction literally against the code as a test — a contract whose two halves are only reviewed by eye will contradict itself.
- L6 — 2026-07-30 10:18 +07 [TASK-20260730-explorer-subagent, coding] mistake: a plan.md deviation note was written with timestamp 10:20 extrapolated from an earlier `date` call (real time was 10:18) — caught and corrected in the same stage → rule: run `date` in the same turn as writing any timestamp; a reading from minutes ago plus mental arithmetic is a guess, not a measurement.
- L7 — 2026-07-30 12:54 +07 [TASK-20260730-explorer-subagent, review] mistake: three verification greps in one review returned false negatives because the prose they searched wraps across lines — `grep "ships with specship for Claude Code"` missed a hit split as `Claude\n  Code`, and `grep -E "^[+-][^+-]"` over a diff silently dropped every changed markdown list item (whose content itself starts with `-`); I twice reported a claim as unconfirmed when the file was correct → rule: verify claims about prose on whitespace-normalised text (`tr '\n' ' ' | tr -s ' '`, or `rg -U`), and when a grep contradicts what you believe the file says, suspect the pattern before the file.
- L8 — 2026-07-30 12:54 +07 [TASK-20260730-explorer-subagent, review] mistake: a shipped README and a spec's Out of Scope both asserted "no other target has a native subagent format" — a factual claim about nine external products, written from assumption with zero sources, and false (Gemini CLI and Copilot both have one); an independent reviewer caught it and primary docs confirmed → rule: never state a capability claim about an external product in shipped text without verifying it (that is what the `research` skill is for); if verification isn't worth the cost, rewrite the sentence to describe only our own behaviour, which needs no source.
- L9 — 2026-07-30 12:54 +07 [TASK-20260730-explorer-subagent, review] mistake: two new agent definitions were installed to a **new** location (`.claude/agents/`) while still citing `` `WORKFLOW.md` `` as if they sat in `.claude/skills/` like every other shipped file, so the one path they told subagents to read did not exist — and the same change shipped artifact templates demanding `path:line` citations that those agents are forbidden to produce → rule: when a file ships to a new install location, re-resolve every relative path in it *from that location*, and when a change adds both a rule and a template the rule must satisfy, execute the pair against each other (the L3 check, applied to prose-vs-prose as well as prose-vs-code).
